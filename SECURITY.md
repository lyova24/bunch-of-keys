# Security policy and threat model

## What the application protects

Keepy is designed to protect vault contents when vault files or
backups are copied from a powered-off or locked machine. Authenticated
encryption also detects accidental corruption and deliberate modification.

The application does not protect secrets from:

- malware, a keylogger, or a debugger running as the same user;
- an administrator or root user on a running system;
- screenshots or screen capture while a value is revealed;
- a clipboard manager that records a copied value before it is cleared;
- memory acquisition while a vault is unlocked;
- a weak master password subjected to offline guessing.

## Cryptographic construction

- Password KDF: Argon2id, version 1.3.
- Default cost: 64 MiB, 3 iterations, 1 lane.
- Vault key: 32 random bytes generated by the operating system RNG.
- Authenticated encryption: XChaCha20-Poly1305.
- Salt: 16 random bytes per vault.
- Nonce: 24 fresh random bytes for every encryption operation.

The unencrypted envelope contains only the format version, vault UUID, KDF
parameters, KDF salt, nonces, and ciphertext. The vault key is encrypted under
the password-derived key. The tree payload is encrypted under the vault key.
Both operations bind the vault UUID and format version as associated data.

KDF parameters read from disk are bounded before allocation to prevent a
modified file from requesting unreasonable memory or CPU resources.

## Runtime handling

- Password strings and cryptographic keys are zeroized on drop where the Rust
  ownership model permits it.
- Masked values are not sent to the native UI until the user explicitly reveals
  them, and their contents are not included in UI search. Explicit copy actions request a value by entry/field ID over private pipes
  and write it with NSPasteboard; private SSH keys are never copied.
- The clipboard is cleared only if its change counter still matches the app’s
  write, avoiding deletion of unrelated clipboard contents.
- A backend inactivity watchdog and macOS sleep/display/session notifications
  lock the vault. Distributed screen-lock notifications provide an additional
  best-effort signal.
- Closing the window hides it; locking explicitly drops decrypted vault data.
  Use the menu bar's `Quit` action to terminate the process.
- Vault files are written atomically and use mode `0600` on Unix. Application
  directories use mode `0700`.

Zeroization is a best effort. Optimizers, allocator copies, the native UI, kernel
buffers, and platform clipboard services can retain copies outside the
application's direct control.

## Reports

Do not include real passwords, tokens, private keys, or vault files in a bug
report. For a private security report, contact the repository owner directly
instead of opening a public issue.
